# Система фильтрации

> **TL;DR:** Frontend строит интерфейс фильтрации на лету, получая метаданные от Backend (`/api/v1/meta/:name/filters`). Backend автоматически парсит JSON-фильтры в SQL с поддержкой подзапросов, иерархий и масштабирования чисел (денег и количества).

> **Тип:** Concept
> **Аудитория:** Developer

---

## 1. Архитектура: Metadata-Driven

Вместо того чтобы вручную писать фильтры для каждого справочника и документа:

1. **Backend** инспектирует структуру (например, `Invoice`) через reflection.
2. Определяет типы полей: `id.ID` → `reference`, `types.MinorUnits` → `money`, `time.Time` → `date`.
3. Отдаёт плоский массив `FilterFieldMeta` на фронтенд.
4. **Frontend** (используя `FilterSidebar`) строит нужные виджеты (Datepicker, Select, Input) на основе `fieldType`.
5. Frontend отправляет массив условий в query-параметре `?filter=[{"field":"...", "operator":"eq", "value":"..."}]`.

## 2. Фильтрация табличных частей (Dot-notation)

Для документа с **зарегистрированной** табличной частью dot-notation может ссылаться на её поля. Следующий SQL — схема расширения для гипотетического товарного документа; `doc_goods_receipts` и товарные строки в текущем контенте отсутствуют.

Он автоматически генерирует SQL `EXISTS` подзапрос:
```sql
EXISTS (
    SELECT 1 FROM doc_goods_receipt_lines
    WHERE doc_goods_receipt_lines.document_id = doc_goods_receipts.id
      AND product_id = $1
)
```
- Оператор `eq` означает: «найди документы, в которых **хотя бы одна строка** содержит этот товар».
- Негативные операторы (`neq`) генерируют `NOT EXISTS`.

> [!WARNING]
> Для работы `EXISTS` подзапросов репозиторий документа обязан зарегистрировать табличную часть (Whitelist) через метод `repo.RegisterTablePart(...)`.

## 3. Масштабирование числовых типов

Metapus не использует числа с плавающей точкой для точных величин. Ограниченные
бизнес-величины хранятся целыми числами (`BIGINT`/`int64`), а сырые суммы
криптоактивов — как `NUMERIC(78,0)`/`RawAmount`. Во внешнем JSON-контракте
криптосуммы передаются каноническими десятичными строками, поэтому браузер не
округляет значения за пределами `Number.MAX_SAFE_INTEGER`.

### Quantity (Статическое масштабирование)
Количество всегда умножается на 10 000. 
Фронтенд присылает десятичную строку `"10"` или JSON number `10`. HTTP-декодер сохраняет исходную запись числа. Сервер определяет Quantity по типу модели или регистрации dataset и проверяет весь результат `100000` на диапазон int64. Допустимо не более четырёх дробных знаков; экспоненты, лишняя точность и переполнение отклоняются без округления.

### Money (Строки minor units)
HTTP принимает каноническую целую строку minor units: например, `"1000"` для 1000 центов. JSON number, дроби и выход за int64 отклоняются. SQL сравнивает сохранённое целое значение без повторного масштабирования по валюте:
```sql
WHERE total_amount = $1 -- аргумент int64(1000)
```

В смешанном списке условие относится к минимальным единицам каждой валюты; UI обозначает единицы ввода. Для отбора по одной валюте дополнительно задаётся валютное измерение. Конвертация валют не выполняется.

Типы и масштабирование определяет сервер: `postgres.ExtractFilterFields[T]` читает реальные типы и `db` tags, а report resolver использует dataset/metadata. `filter.Resolve` создаёт проверенное условие, которое принимает SQL builder. Присланные `fieldType`/`scale` остаются подсказками отображения и не меняют семантику. Один контракт применяется к полям шапки, табличным частям, связанным полям и отчётам. Внутренние JSONB/JWS/HMAC codecs не меняются.

## 4. Операторы и Иерархия

Поддерживаются стандартные операторы: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `in`, `nin`, `contains`, `null`, `not_null`.

**Специальные операторы:**
Для справочников с иерархией (`ParentID`) доступны операторы `in_hierarchy` и `nin_hierarchy`.
Они автоматически разворачиваются в рекурсивный CTE (Common Table Expression), позволяя одним условием выбрать "Папку А и все вложенные в неё подпапки и элементы".

> [!NOTE]
> Защита от SQL-инъекций гарантируется Whitelist-проверкой: если `item.Field` нет в списке разрешённых полей, фильтр отклоняется до построения SQL-запроса.
