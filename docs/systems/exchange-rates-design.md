# Курсы валют для криптопроцессинга: первая версия

> **Тип:** Reference · **Аудитория:** Developer, Product, AI-Agent
> **Статус:** Первая версия реализована в рабочем дереве и проверена 2026-09-06.
> **Связанные:** [Эксплуатация и настройка](exchange-rates.md), [Транзакции](transactions.md), [Системные настройки](settings-system.md).

## Назначение и границы

Подсистема оценивает криптовалютные остатки Portal и предоставляет ERP рабочее место «Деньги → Курсы валют». Котировка объясняет оценку на конкретный момент; она не задаёт условия исполнения платежа, инвойса или вывода.

| Решение | Первая версия |
|---|---|
| Провайдер | CoinGecko Demo, один выбранный источник по UUID |
| Валюта оценки | USD; обе валюты хранятся в каждой записи |
| Получение | Каждые 300 секунд, пакеты до 250 уникальных внешних ID |
| Актуальность | Возраст от времени провайдера строго меньше 900 секунд |
| История | Неизменяемые наблюдения без автоматической очистки |
| Изменение настроек | Через ERP; ключ и новые соответствия подхватываются без рестарта |
| Обновление списка | Только повторное чтение сохранённых данных |
| Схема | Исходные миграции для новой БД; для заполненных окружений — явный [операторский перенос интеграций](../operations/integration-accounts.md), без reset |

ERP-принцип — периодический регистр сведений, доступный пользователям, и явное ограничение возраста курса. См. [1С: регистры сведений](https://1c-dn.com/library/tutorials/practical_developer_guide_understanding_information_registers/) и [ERPNext: допустимый возраст курса](https://docs.frappe.io/erpnext/exchange-rate-field-frozen).

## Схема и неизменяемая история

Исходная миграция `00006_crypto_core.sql` определяет:

- `reg_exchange_rates`: UUID v7, `currency_id`, `base_currency_id`, `rate_source_id`, `rate NUMERIC(38,18)`, целая положительная `multiplier`, `provider_updated_at`, `received_at`, `recorded_at`, `version`, `mapping_version`, `feed_attempt_id`, CDC-поля.
- `reg_rate_source_mappings`: ключ `(currency_id, base_currency_id, rate_source_id)`, внешний ID, активность и версия. Изменение — атомарные DELETE + INSERT с проверкой ожидаемой версии и событием аудита, содержащим прежние и новые значения.
- `sys_rate_feed_state`: одна строка на источник и валюту пересчёта, срок запуска, token и срок lease, последнее завершение, последняя попытка и пригодный результат, счётчики и диагностика.

Семантика: `multiplier × исходная валюта = rate × валюта оценки`. У CoinGecko кратность равна 1. Домен проверяет представимость цены **до INSERT**: никакого float или скрытого округления PostgreSQL.

Уникальны версия внутри пары/источника/времени провайдера и пара внутри попытки импорта. Индексы обслуживают последнее наблюдение и историю с продолжением. Триггер запрещает UPDATE и DELETE котировок; публичных команд изменения котировки нет. История не очищается по возрасту.

Новый timestamp сохраняется даже при прежней цене. При том же timestamp сравнивается последняя принятая версия: повтор пропускается, изменение создаёт следующую. `A → B → A` сохраняет три версии. Порядок версий описывает порядок принятых системой наблюдений, а не доказанный порядок исправлений провайдера.

Внешний ID меняется с увеличением версии соответствия. Старые котировки остаются в истории, но не применяются до получения по новой версии. Выключение источника или соответствия прекращает применение. Тип используемого источника изменить нельзя; ограничение проверяется сервисом и БД.

## Настройки и загрузчик

`sys_settings.exchange_rates` и типизированная секция API `exchangeRates` содержат только `sourceId`. Seed записывает UUID созданного CoinGecko-источника, если выбор пуст. Переименование не меняет выбор.

Цикл запускается для каждого tenant независимо от наличия соответствий. Перед попыткой читает выбранный источник и актуальные соответствия. Для каждой группы уникальных CoinGecko ID выполняется запрос Demo `/simple/price` с `vs_currencies=usd`, `include_last_updated_at=true`, `precision=full`. Один внешний ID может обслуживать несколько явно настроенных соответствий.

CoinGecko Demo API key хранится в `cat_rate_sources.api_key` как универсальный реквизит источника и передаётся заголовком `x-cg-demo-api-key`. Администратор заменяет или очищает его в обычной ERP-форме с optimistic locking; worker перечитывает реквизит перед каждой попыткой, поэтому рестарт не требуется. API чтения возвращает только `apiKeyConfigured`, сохранённое значение не сериализуется и не попадает в Portal или журнал событий. Произвольный URL и приоритет не редактируются. `rateLimitRpm` ограничивает частоту запросов данного источника. Таймаут запроса — 15 секунд. HTTP выполняется вне транзакции.

Отсутствующая цена, неположительное или непредставимое число, отсутствие времени, время в будущем — ошибки пары. Ошибка отдельной пары не мешает сохранить остальные. Время получения фиксируется после чтения ответа. При отсутствии ключа состояние загрузки показывает проблему конфигурации, остальные задачи продолжаются.

### Владение попыткой

1. Атомарно захватить наступившую работу при свободном или истёкшем lease.
2. Выдать token на 120 секунд, продлевать каждые 30 секунд.
3. Выполнить HTTP и проверить ответ.
4. В короткой транзакции проверить token и живой lease, заблокировать настройки источника и проверяемые соответствия, повторно проверить их версии.
5. Записать пригодные пары и состояние завершения одной транзакцией. Ошибка INSERT откатывает пакет целиком.
6. Назначить следующий запуск через 5 минут; HTTP 429 может отложить его до более позднего `Retry-After`.

Опоздавший ответ потерявшего владение worker не записывается. Повтор завершённой попытки не создаёт дублей. Журнал worker дополняет состояние загрузчика, но не заменяет его. Счётчики: запрошено, пригодно, новых, повторов и отклонённых пар.

## Resolver и оценка баланса

Доменный resolver делает один запрос для уникальных валют всех строк. Выбирает максимальное время провайдера не позднее времени оценки, затем максимальную версию. После выбора проверяет источник, соответствие, его версию и TTL. Более старая котировка не заменяет устаревшую или котировку прежнего соответствия.

| Состояние | Основные причины |
|---|---|
| `identity` | USD → USD, коэффициент 1, без записи в регистре |
| `fresh` | Пригодная котировка |
| `stale` | Возраст 900 секунд или больше |
| `missing` | Нет выбранного источника, соответствия, котировки или связи токена с валютой; соответствие изменилось |
| `disabled` | Выключен источник или соответствие |

Результат содержит применённую котировку либо null, последнее известное наблюдение, время оценки и границу актуальности. Ошибка БД не превращается в отсутствие курса.

`cryptoapp.ValuationService` (оценка криптобалансов живёт в конфигурации и только использует курсы платформы) читает подтверждённые остатки, ожидание, настройки, валюты и курсы в `REPEATABLE READ READ ONLY` через `TxManager`. После завершения транзакции выполняет точную конвертацию и строит DTO.

Подтверждённый регистр содержит доступные средства; «Всего» = «Доступно» + «В ожидании». Позиции только с ожиданием тоже включаются. Нативные количества сохраняются при любой доступности курса. Все промежуточные операции используют точное рациональное представление. Строки и агрегаты округляются при формировании DTO по `decimalPlaces` USD, половины от нуля; итог округляется после суммирования.

Каждая карточка имеет независимые `amount`, `coverage=complete|partial|none`, `unvaluedCount`. Нулевые позиции не ухудшают полноту. Если нет оценённых ненулевых позиций и есть неоценённые ненулевые позиции, сумма null. Полностью нулевой баланс — 0 с `complete`.

## API и права

Маршруты ERP относительны `/api/v1`:

| Метод и маршрут | Право |
|---|---|
| GET `/registers/exchange-rates/current` | `register:exchange_rate:read` |
| GET `/registers/exchange-rates/history` | то же |
| GET `/registers/exchange-rates/:id` | то же |
| GET `/catalog/rate-sources/:id/mappings` | `catalog:rate_source:read` |
| PUT `/catalog/rate-sources/:id/mappings/:currencyId/:baseCurrencyId` | чтение и `catalog:rate_source:update` |
| GET `/catalog/rate-sources/:id/feed-state` | `catalog:rate_source:read` |

Регистрация проходит через фабрики. Подресурсы подключаются необязательным интерфейсом `CatalogSubresourceRegistration`; router не содержит специальной ветки источника.

UUID и время передаются строками, курсы и деньги — decimal-строками, отсутствующие значения — null. PUT соответствия принимает `externalId`, `isActive`, `expectedVersion`; 0 означает создание, конфликт — AppError с HTTP 409.

Срез: активные валюты, включая отсутствие котировки и USD identity; фильтры `currencyId`, `status`, сортировка по коду и UUID. История: `currencyId`, необязательные `baseCurrencyId`, `sourceId`, `from`, `to`; период `[from,to)` максимум 31 день, по умолчанию сутки; порядок времени провайдера, версии и UUID по убыванию. Размер страницы по умолчанию 50, максимум 100. `nextCursor` связан с фильтрами. Период запроса не ограничивает хранение.

Seed выдаёт чтение регистра admin/accountant/manager/user, настройку источника — admin. Выбор источника остаётся в административных системных настройках. UI получает коды собственных прав через `/auth/me/permissions`; административная роль без `isAdmin` проверяется обычными разрешениями.

Оба Portal balance endpoint возвращают единый структурированный контракт. Клиентский параметр `source`, включая пустой, отклоняется с 400. Portal ограничен merchant scope и не получает настройки интеграции, mapping version, import token или секреты. Merchant Public API не меняется.

## Интерфейс

ERP: `/finance/exchange-rates`, пункт в группе «Деньги», command palette и название вкладки. Фильтры и открытые панели отражаются в URL. Список показывает кратность, курс, источник, время провайдера и получения, состояние и причину. Детали доступны кнопками с клавиатуры и касанием. История показывает все сохранённые версии и позволяет открыть конкретную запись по ссылке.

Форма источника расширяет AutoForm редактором соответствий. Конфликт не стирает ввод; повторное сохранение явно применяет его к загруженной новой версии. Закрытие изменённого редактора требует подтверждения. Состояние загрузчика показано отдельно: ошибка последней попытки не делает свежий курс устаревшим.

Оба экрана баланса Portal используют общий компонент и панель «О курсе», сохраняющую котировку показанного расчёта. Достижение `freshUntil` вызывает обновление; неудача помечает сохранённую оценку устаревшей. `decimal.js` форматирует значения без Number/parseFloat и без клиентской подстановки валюты. Старые приблизительные суммы в списке инвойсов, вычислявшиеся по символу токена на клиенте, удалены: оценка операций требует отдельного будущего контракта.

## Проверки

- Домен: TTL 899/900, состояния и identity, дедупликация валют, точная кратность, малые цены, большие суммы, округление после агрегации, независимая полнота карточек.
- PostgreSQL: неизменяемость, версии и повторы, конкурентное владение, истечение lease, изменение соответствий, откат пакета, курсоры и изоляция снимка.
- Worker: локальный HTTP-сервер вместо CoinGecko, пакетирование, частичный/пустой/невалидный ответ, отсутствие ключа, 429 и timeout, добавление соответствия без рестарта.
- API/UI: разрешённая роль без admin bypass, запрет настройки читателю, отсутствие секретов и чужих позиций Portal, конфликт формы, клавиатура, история, точность и истечение актуальности.

Обязательные команды: `go build ./...`, `golangci-lint run ./...`, `go test -short -race ./...`, целевые integration-тесты, `npx tsc --noEmit`, `npm run lint`, целевые Playwright-сценарии. Интеграция выполняется только на отдельной свежей БД.

### Результат проверки 2026-09-06

Прошли `go build ./...`, `go test -short -race ./...`, `golangci-lint v2.13.1` (0 замечаний), `npx tsc --noEmit`, `npm run lint` (0 ошибок и предупреждений). Linter запущен через `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.13.1 run ./...`.

Целевые integration-тесты с `-race` прошли в пакетах `register_repo`, `rate_feed` и `content`. Проверены свежие исходные миграции, две tenant-БД, согласованный снимок при конкурентном подтверждении, запрет записи после потери lease (включая истечение перед завершением транзакции), повторные ответы и версии, частичные ответы и изменение соответствия во время HTTP. Проверка чтения и запрета настройки использует сохранённого пользователя роли `user` с `isAdmin=false` и правами из БД.

Четыре Playwright-сценария прошли: чтение/история/клавиатура, отказ без разрешения, точность и истечение актуальности Portal, конфликт и закрытие редактора. Выполнена визуальная проверка ERP и Portal, включая большую сумму. HTTP CoinGecko заменён локальным сервером; реальный Demo-ключ и доступ к провайдеру в этих тестах не использовались. Существующие заполненные tenant-БД не изменялись.

## Дальнейшее развитие, исключённое из первой версии

Ручные котировки, резервные источники и fallback, кросс-курсы, исторические политики и API knownAt, оценка в других валютах, коммерческие котировки для исполнения операций, фиатные инвойсы, команды внеочередной загрузки и брокер команд. Миграция заполненных tenant-БД — отдельная задача; текущие исходные миграции к ним не применять.
