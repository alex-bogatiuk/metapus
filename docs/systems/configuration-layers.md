# Слои приложения: платформа, базовая конфигурация, надстройка

> **TL;DR:** Приложение Metapus — три слоя. Платформа — механизмы (формы, проведение, регистры, права), как 1С:Предприятие с БСП. Базовая конфигурация — самодостаточная бизнес-логика, как типовая УНФ. Надстройка — необязательная отраслевая специфика над одной конкретной базой. У тенанта ровно одна база и не больше одной надстройки.
> **Тип:** Concept
> **Аудитория:** Developer

## Слои

| Слой | Что это | В репозитории |
|---|---|---|
| Платформа | Механизмы без бизнес-логики: построение форм и списков, проведение, регистры, права, отчёты, печать, загрузка данных | `internal/`, публичный API — `pkg/sdk` |
| Базовая конфигурация | Самодостаточная бизнес-логика. Платформы и базы достаточно для автоматизации бизнеса | [`configurations/trade`](../../configurations/trade) («Торговля и сервис»), [`internal/configuration/crypto`](../../internal/configuration/crypto) (криптопроцессинг) |
| Надстройка | Необязательная отраслевая специфика над одной конкретной базой: новые объекты, реквизиты и движения, изменение поведения базы в объявленных ею точках | [`configurations/automotive`](../../configurations/automotive) («Автобизнес» над «Торговлей и сервисом») |

`internal/configuration/none` — платформа без конфигурации.

## Одна надстройка

У тенанта не больше одной надстройки. Две отрасли в одном приложении («Автозапчасти» и «Автосервис») — это отдельная надстройка, которая их объединяет: её разработчик собирает её из пакетов обеих отраслей, сам решает их пересечения и отвечает за совместимость с базой и платформой. Поэтому надстройки не встречаются во время работы и не конфликтуют.

## Контракт

Базовая конфигурация — обычная `configuration.Configuration`. Если на ней строятся надстройки, она объявляет версию (`configuration.Versioned`, `Version()`, MAJOR.MINOR.PATCH). Её пакеты, которые импортирует надстройка, — её публичный API: добавления в них поднимают минорную версию, несовместимые изменения — мажорную.

Надстройка — `configuration.AddOn`:

```go
func (automotive) Base() configuration.Configuration { return trade.Trade() }
func (automotive) BaseVersion() string               { return "1.0.0" }
```

Платформа ([`internal/configuration/stack.go`](../../internal/configuration/stack.go)) на старте каждого процесса собирает стек (`Assemble`) и проверяет его (`CheckStack`):
- база надстройки — не надстройка;
- база объявляет версию той же мажорной и не младшей минорной, чем `BaseVersion`;
- платформа обслуживает `APIVersion` обоих слоёв.

Собранное приложение регистрирует, обслуживает (`Server`), запускает в воркере и засевает (`Seed`) сначала базу, потом надстройку. Маршрутные модули и модули проведения обоих слоёв складываются. Каталог интеграций берётся у надстройки, если она его объявляет, иначе у базы. Имя приложения — имя надстройки.

## Импорты

Закреплено тестами `internal/architecture`:
- база импортирует из платформы только `pkg/sdk` и не знает о надстройках;
- надстройка импортирует только `pkg/sdk` и пакеты своей базы;
- платформа не импортирует ни базы, ни надстройки;
- конфигурации-соседи не импортируют друг друга.

База, на которой строятся надстройки, живёт вне `internal/` (`configurations/`): надстройку из другого репозитория Go пустит к ней, а к `internal/` — нет.

## Тенант и миграции

У каждого слоя своя история миграций: `goose_db_version` платформы, `goose_db_version_<база>`, `goose_db_version_<надстройка>`. В метабазе у тенанта записаны база (`configuration`) и надстройка (`addon`) с версиями схемы каждой ([`db/meta/00003_tenant_addon.sql`](../../db/meta/00003_tenant_addon.sql)). Сервер сверяет со своими ожиданиями все три версии.

Тенанта базы можно перевести на надстройку: `<надстройка>-tenant migrate` применит её миграции и запишет её. Снять надстройку или заменить её на другую нельзя.

## Команды и фронтенд

У базы и у надстройки свои команды: `cmd/trade-*` запускают «Торговлю и сервис» одну, `cmd/automotive-*` — её с надстройкой. Манифест фронтенда надстройки называет базу:

```json
{ "register": "registerAutomotiveConfiguration", "base": "trade" }
```

`npm run configure -- automotive` собирает `app/` из базы и надстройки: база регистрируется первой, страницы базы подключаются, страница надстройки заменяет страницу базы с тем же маршрутом. `go run ./cmd/http-contracts` пишет фронтенд-файлы каждого слоя в его собственную папку.

## Пока нет

Этап B — механизмы надстройки:
- реквизиты надстройки к справочникам, документам и строкам документов базы (в собственных таблицах «один к одному»);
- движения надстройки к документам базы;
- объявленные точки замены поведения базы (цена, себестоимость, заполнение на основании, статусы, нумерация).
