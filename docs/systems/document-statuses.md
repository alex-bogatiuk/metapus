# Статусы документов

> **TL;DR:** Документ объявляет статусную модель в своём `entity.Definition`: колонку статуса, начальный статус, статусы с названиями и разрешённые переходы, у перехода может быть своё право. Платформа проверяет модель при каждой записи документа, записывает историю статусов и показывает её в форме.
> **Тип:** Concept
> **Аудитория:** Developer

## Объявление

```go
var Definition = entity.Definition{
	Key: "customer_order", /* … */
	Statuses: entity.StatusModel{
		Column: "status", Initial: "open",
		Values: []entity.StatusValue{{Value: "open", Label: "Открыт"}, {Value: "in_progress", Label: "В работе"}, /* … */},
		Transitions: []entity.StatusTransition{
			{From: []string{"open"}, To: "in_progress"},
			{From: []string{"completed", "cancelled"}, To: "in_progress", Permission: "reopen", Label: "Возобновление закрытого заказа"},
		},
	},
}
```

- `Column` — колонка документа со статусом, поле строкового типа (свой `type Status string` подходит).
- `Initial` — статус документа, записанного без статуса. Новый документ может начаться в начальном статусе или в любом, куда из него ведёт переход.
- `Values` — все статусы в порядке, в котором их показывает форма. Названия идут в сообщения об ошибках, в варианты поля статуса и в историю.
- `Transitions` — разрешённые смены. Переход без `From` ведёт в `To` из любого статуса. Без переходов разрешена любая смена между `Values`; если объявлен хотя бы один, смена, которую не разрешает ни один переход, отклоняется. Запись документа в том же статусе перехода не требует.
- `Permission` — действие права `<вид>:<ключ>:<действие>` (например, `document:customer_order:reopen`). Право появляется в редакторе ролей само ([`permissions.go`](../../internal/infrastructure/http/v1/permissions.go)): называется `<документы>: <Label>`. Без `Permission` достаточно права на изменение документа. Администратор и системные запросы без пользователя проходят любой объявленный переход. Несколько переходов могут делить одно право.

`Definition.Validate` отклоняет модель, в которой статус объявлен дважды или без названия, начальный статус или статус перехода не входит в `Values`, а право перехода совпадает со стандартным действием (`read`, `create`, `update`, `delete`, `post`, `unpost`).

## Что делает платформа

Проверка стоит в репозитории документа ([`document_repo/base.go`](../../internal/infrastructure/storage/postgres/document_repo/base.go), `statusChange`), как и [дата запрета](settings-system.md). Через него проходит каждая запись: форма, проведение, ввод на основании, копирование, хуки. Действует для репозиториев из `NewDocumentRepoForDefinition`, то есть для объявленных документов (`registry.Document`) и ручных регистраций с `Definition`.

| Случай | Ответ |
|---|---|
| Статуса нет в `Values` | 422, `DOCUMENT_STATUS_UNKNOWN` |
| Ни один переход не разрешает смену | 422, `DOCUMENT_STATUS_TRANSITION_NOT_ALLOWED`: «Нельзя перевести документ из статуса «В работе» в статус «Новая»» |
| Переход требует права, которого у пользователя нет | 403, `FORBIDDEN`: «Нет права переводить документ в статус «…»», деталь `required_permission` |

Проверка ([`domain.CheckStatusChange`](../../internal/domain/document_status.go)) сравнивает статус записи со статусом в базе. Конкурентную запись отсекает оптимистическая блокировка по `version`.

**История.** Каждая запись документа в новом статусе, включая первую, добавляет строку в `sys_document_status_history` в той же транзакции: тип документа, его ID, статус, прежний статус, время, автор ([миграция 00008](../../db/migrations/00008_document_status_history.sql)). Отклонённая запись строки не оставляет. История удалённого документа сохраняется. `GET /document/<route>/:id/status-history` (право `:read`) сначала читает документ с политиками пользователя (RLS, CEL). Если политика полей скрывает колонку статуса, история приходит пустой.

**Метаданные.** `statuses` в метаданных документа ([`metadata/statuses.go`](../../internal/metadata/statuses.go)) — поле статуса, начальный статус, статусы и переходы с кодами прав. Варианты поля статуса берутся из модели, отдельный `RegisterEnum` не нужен.

**Форма.** Поле статуса предлагает текущий статус документа и те, куда из него ведёт переход ([`lib/document-status.ts`](../../frontend/lib/document-status.ts)). Переход с правом тоже предлагается, право проверяет сервер. Кнопка «История статусов» на панели формы открывает историю ([`document-status-history-dialog.tsx`](../../frontend/components/shared/document-status-history-dialog.tsx)).

## Состояния заказа покупателя

В «Автозапчастях» пользователь выбирает у заказа состояние из справочника, а статус заказа ставит обработчик `ApplyState` по состоянию. Статусная модель заказа объявлена на статусах: работа и обратно, выполнение и отмена из открытого или рабочего, возобновление закрытого заказа по праву `document:customer_order:reopen`. Регистр конфигурации «История состояний заказов» по-прежнему хранит состояния: они подробнее статусов («Ожидает предоплаты» и «Новый» — оба открыты). Платформенная история хранит статусы.

## Пока нет

- Статусов у справочников.
- Отдельной команды «Перевести в статус» без открытия формы, в том числе для группы документов из списка.
- Запрета изменения документа в статусе (например, только чтение у выполненного заказа).
- Поведение перехода (проверка, движения) задаёт сам документ в хуке, как `ApplyState` у заказа; платформенного обработчика на переход нет.
