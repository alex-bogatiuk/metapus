# Система отчётов (Reporting System)

> **TL;DR:** Встроенный Query Engine (аналог СКД из 1С). Разработчик только декларирует Dataset (какие таблицы и поля доступны), а платформа сама строит SQL, генерирует UI (фильтры, колонки), обрабатывает экспорт в XLSX и сохраняет пользовательские варианты отчёта.

> **Тип:** Concept
> **Аудитория:** Developer
> **Связанные:** [filtering.md](filtering.md)

---

## 1. Архитектура Query Engine

Классические отчёты требуют написания сложного SQL для каждого набора фильтров. В Metapus разработчик описывает метаданные отчёта (Dataset), а `Compiler` динамически генерирует SQL на основе того, какие колонки и фильтры выбрал пользователь на фронтенде.

**Процесс выполнения:**
1. **Frontend:** Запрашивает метаданные отчёта (`GET /reports/{key}/metadata`). Платформа возвращает дерево доступных полей (включая связанные справочники).
2. **Frontend:** Пользователь выбирает колонки (например, "Контрагент.ИНН") и настраивает фильтры. Отправляется POST-запрос с `QueryRequest`.
3. **Backend Compiler:**
   - Валидирует запрошенные поля по Whitelist'у.
   - Разрешает ссылки (`Resolve reference paths`). Если запрошено поле "Контрагент.ИНН", автоматически добавляет `LEFT JOIN cat_counterparties`.
   - Применяет `AdvancedFilters` (спускает их в секцию SQL `WHERE`).
   - Генерирует `GROUP BY`, `ORDER BY`, `LIMIT/OFFSET`.
   - Выполняет запрос к PostgreSQL (`pgx`) и отдаёт массив строк.

## 2. Экспорт и Варианты отчётов

Помимо обычного просмотра в виде таблицы:
- **Экспорт (XLSX):** Платформа сама генерирует Excel-файл с учетом группировок (Control Breaks) и форматов данных.
- **Варианты (Variants):** Пользователь может сохранить набор выбранных колонок, сортировок и фильтров как "Вариант отчёта" (аналог пресетов). Варианты хранятся в `sys_report_variants` и могут быть личными или общими для всех пользователей тенанта.

## 3. Как создать новый отчёт

1. Объявить `schema.Dataset` и источники/поля по аналогу `internal/content/report_datasets.go`; при необходимости добавить `DatasetExecutor`.
2. Подключить dataset и его permission к реестру: `registerReportRoutes` в `internal/infrastructure/http/v1/routes_documents.go` строит compiler и монтирует generic handlers.
3. Проверить authorized read declarations, денежные единицы и разрешённые связи/фильтры.
4. Generic frontend расположен по `/reports/{key}`; проверьте metadata/navigation и HTTP route contracts. Метод `FactoryRegistry.RegisterReport` в текущем API отсутствует.

## Права на сохранённые конфигурации

Доступность конфигурации и право её изменения проверяются отдельно. Личную конфигурацию изменяет автор; общую — автор или системный администратор; системную — системный администратор. Роль `security_admin` сама по себе не даёт этих бизнес-прав. Создание системной конфигурации и перевод существующей в `system` требуют администратора. Системная конфигурация не имеет автора; при выходе из `system` автором становится действующий администратор.

Сервис вариантов отчётов проверяет зарегистрированный dataset и его permission при создании, изменении, удалении и чтении списка. Dataset существующей записи не меняется по входному запросу. `UPDATE` сравнивает ожидаемую версию в SQL; конфликт возвращает HTTP 409. Удаление также использует версию записи, на которой была выполнена проверка прав.

Сохранённые представления списков используют ту же политику прав. Переключение default и запись представления выполняются в одной транзакции, с сериализацией по entity/visibility/author; чужие авторские defaults не сбрасываются. Сброс default увеличивает версию изменённой записи. Частичный уникальный индекс обеспечивает один активный default в этой области. При конфликте версии вся операция откатывается.
