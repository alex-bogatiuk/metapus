# Frontend Guidelines

> **TL;DR:** Адаптация Clean Architecture под React/Next.js. Strict TypeScript, URL-driven state, UI только на базе shadcn/ui.

> **Тип:** Reference
> **Аудитория:** Developer
> **Связанные:** [03-project-structure.md](../guide/03-project-structure.md)

---

## 1. Фундаментальные принципы

### 1.1 Code is Metadata
Пользовательский интерфейс строится на строгих контрактах с бекендом.
- **Type Safety**: API-данные получают конкретный тип после runtime-проверки. `any` не используется; `unknown` допустим на внешней границе до Zod/contract validation.
- **Contract Integrity**: Если бекенд возвращает DTO `InvoiceResponse`, фронтенд обязан иметь идентичный TypeScript `interface` с теми же полями и правилами nullability.

### 1.2 URL-driven State
Избегайте скрытого состояния для навигации.
- Сортировки и фильтры списков синхронизируются с URL. Открытые вкладки, их кеш и dirty state хранятся в Zustand; курсоры и восстановление страницы зависят от конкретного list hook.
- Пользователь должен иметь возможность скопировать URL и отправить коллеге, который увидит ровно ту же выборку.

### 1.3 UI Kit Restriction
> [!IMPORTANT]
> Весь UI строится исключительно на базе Tailwind CSS + **shadcn/ui**.

- Запрещено писать базовые примитивы (Button, Input, Select, Dialog) с нуля.
- Запрещено использовать хардкодные HEX-цвета. Все цвета берутся из Tailwind токенов (например, `bg-background`, `text-muted-foreground`).

## 2. Архитектура файлов (Feature-Sliced/Vertical)

Код разделяется по функциональным "срезам", а не по типу файлов.

```path
frontend/app/(main)/
├── catalogs/[routePrefix]/     # Generic catalog routes
├── documents/[routePrefix]/   # Generic document routes
└── reports/[key]/             # Metadata-driven reports
```

1. **Page Components (`page.tsx`)**: ERP-страницы преимущественно клиентские (`"use client"`): связывают list/form hooks, metadata и вкладки. Layout и отдельные страницы могут быть серверными.
2. **Feature Components**: Клиентские формы, таблицы. Лежат рядом со срезом или в `components/shared/`.
3. **UI Components**: Только в `components/ui/`. Ничего не знают о бизнесе (DUMB components).

## 3. Обработка данных

- Все HTTP-запросы должны проходить через централизованную утилиту (`apiFetch`), которая добавляет `X-Tenant-ID` и обрабатывает 401/403.
- Для форм используется единый хук `useFormDraft` (для автосохранения) и интеграция с React Hook Form + Zod.
- Если загрузка долгая — используйте Skeleton-паттерн (`DataTableSkeleton`), а не просто крутящийся спиннер.

### Зависимости и конкурирующие запросы

- Не подавляйте `react-hooks/exhaustive-deps`: значения запроса входят в зависимости, а действия события выносятся в обработчик или `useEffectEvent`.
- Для списков с кэшем вкладок используйте `useCachedLoad`: он пропускает начальную загрузку из кэша, но загружает данные при изменении фильтров. Отдельные эффекты монтирования и фильтров вызывают двойную загрузку.
- `useLatestRequest` защищает состояние от ответа предыдущего запроса, размонтирования и смены сессии. Основная загрузка вызывает `begin()`, пагинация — `capture()`; перед применением результата, ошибки и сбросом индикатора проверяется возвращённая функция.
- Связанные поля формы храните в типизированном объекте. `useFormDraft.setField` поддерживает изменение одного поля и функциональное обновление. Страница соединяет UI с хуком формы; загрузка, сохранение и проверка данных остаются в хуке.
