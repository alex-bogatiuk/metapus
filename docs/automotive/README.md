# Надстройка «Автобизнес»

> Надстройка третьего уровня ([слои приложения](../systems/configuration-layers.md)) над базовой конфигурацией [«Торговля и сервис»](../trade/README.md): специфика магазина автозапчастей и автосервиса (СТО) в одной надстройке. Код — [`configurations/automotive`](../../configurations/automotive), требования — [`configuration-requirements/`](../../configurations/automotive/configuration-requirements).

Как специфика автомагазина и автосервиса из документа по 1С:УНФ ложится на платформу, базу и надстройку, что из неё должно появиться в базе и в каком порядке всё делать — в [архитектуре надстройки](architecture.md).

Пока надстройка ничего не добавляет: тенант «Автобизнеса» — это тенант «Торговли и сервиса» с записанной надстройкой. Объекты и реквизиты автобизнеса появятся с механизмами надстройки (этап B): реквизиты к объектам базы, движения к её документам, объявленные точки замены поведения.

- База — `trade` версии 1.0 (`BaseVersion`). Платформа не запустит надстройку на базе другой мажорной версии или младшей минорной.
- Надстройка импортирует только `pkg/sdk` и пакеты своей базы; база о надстройке не знает. Это проверяет `internal/architecture`.
- Миграции надстройки — свои, со своей историей `goose_db_version_automotive`; сейчас их нет.

## Запуск

| Что | Команда |
|---|---|
| API-сервер | `go run ./cmd/automotive-server` |
| Воркер | `go run ./cmd/automotive-worker` |
| Тенанты (`init-meta`, `create`, `migrate`) | `go run ./cmd/automotive-tenant …` |
| Сид (с `SEED_DEMO_DATA=true` — демо базы) | `go run ./cmd/automotive-seed` |
| Фронтенд | `cd frontend && npm run configure -- automotive && npm run dev` |

Сервер надстройки обслуживает тенантов `trade+automotive`. Тенанта одной базы `automotive-tenant migrate` переводит на надстройку; снять надстройку с тенанта или заменить её нельзя.
