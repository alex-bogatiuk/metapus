# Надстройка «Автобизнес»

> Надстройка третьего уровня ([слои приложения](../systems/configuration-layers.md)) над базовой конфигурацией [«Торговля и сервис»](../trade/README.md): специфика магазина автозапчастей и автосервиса (СТО) в одной надстройке. Код — [`configurations/automotive`](../../configurations/automotive), требования — [`configuration-requirements/`](../../configurations/automotive/configuration-requirements).

Как специфика автомагазина и автосервиса из документа по 1С:УНФ ложится на платформу, базу и надстройку, что из неё должно появиться в базе и в каком порядке всё делать — в [архитектуре надстройки](architecture.md).

Что уже есть — **реквизиты к номенклатуре базы** (`item`): бренд и нормализованный артикул ([`domain/catalogs/item_automotive`](../../configurations/automotive/domain/catalogs/item_automotive)).
- Они лежат в таблице надстройки `cat_items__automotive` один к одному с `cat_items`. Форма, список, фильтры и загрузка номенклатуры базы показывают их в группе «Автобизнес» ([механизм](../systems/configuration-layers.md#этап-b-реквизиты-надстройки)).
- Нормализованный артикул — артикул в верхнем регистре без `-`, `/`, `.` и пробелов. Его заполняет хук записи надстройки, на колонке индекс. Поиск списка номенклатуры находит позицию по началу нормализованного артикула: `W712-75` и `w 712/75` находят `W71275`. У позиций, которые были у тенанта до установки надстройки, его заполняет миграция.
- Бренд пока строка. Справочник брендов `part_brand` с синонимами и классами качества появится вместе со ссылками в расширениях ([решение](architecture.md#85-бренд-номенклатуры--пока-строка)). Строковый «Производитель» базы остаётся для неавтомобильных товаров.

Остальные объекты автобизнеса появятся со следующими механизмами этапа B: реквизитами к документам базы, движениями к её документам, объявленными точками замены поведения.

- База — `trade` версии 1.0 (`BaseVersion`). Платформа не запустит надстройку на базе другой мажорной версии или младшей минорной.
- Надстройка импортирует только `pkg/sdk` и пакеты своей базы; база о надстройке не знает. Это проверяет `internal/architecture`.
- Миграции надстройки — свои, со своей историей `goose_db_version_automotive` ([`db/configuration/automotive`](../../db/configuration/automotive)).

## Запуск

| Что | Команда |
|---|---|
| API-сервер | `go run ./cmd/automotive-server` |
| Воркер | `go run ./cmd/automotive-worker` |
| Тенанты (`init-meta`, `create`, `migrate`) | `go run ./cmd/automotive-tenant …` |
| Сид (с `SEED_DEMO_DATA=true` — демо базы) | `go run ./cmd/automotive-seed` |
| Фронтенд | `cd frontend && npm run configure -- automotive && npm run dev` |

Сервер надстройки обслуживает тенантов `trade+automotive`. Тенанта одной базы `automotive-tenant migrate` переводит на надстройку; снять надстройку с тенанта или заменить её нельзя.
