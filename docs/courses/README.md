# Курс по Go и архитектуре Metapus (для 1С-программиста)

Добро пожаловать в Metapus! Вы — 1С-разработчик, и вы привыкли к встроенным механизмам проведения, регистрам и конфигуратору. Здесь мы создаём всё это «с нуля», но с помощью мощных и гибких паттернов проектирования.

Этот курс построен так, чтобы вы изучали Go **сразу на примере нашей кодовой базы** и чтобы у вас не осталось «слепых зон».

---

## Как проходить курс

1. **Читайте теорию и примеры.** Каждый модуль содержит примеры из реальных файлов проекта.
2. **Ставьте Breakpoint'ы.** Открывайте указанные файлы в IDE (VS Code или GoLand) и ставьте красную точку.
3. **Нажимайте F10/F11.** F10 — шаг на следующую строку. F11 — провалиться внутрь вызываемой функции.
4. **Изучайте Variables.** В боковой панели отладчика смотрите текущие значения переменных, их типы, адреса памяти.

---

## Настройка окружения

### Установка Go

1. Скачайте Go с [go.dev/dl](https://go.dev/dl/) (версия 1.27+).
2. Убедитесь, что `go version` работает из консоли.

### Подготовка API и отладчика

Сначала выполните [локальный bootstrap](../crypto/crypto-environment-setup.md). Он создаёт tenant-БД, seed, Vault-конфигурацию, approval keys/policy bundle и `.env.crypto.local`. Одних JWT_SECRET и DATABASE_URL для запуска server недостаточно.

Проверьте обычный запуск `pwsh ./scripts/dev/crypto-run-server.ps1`. Для отладки остановите этот процесс, чтобы освободить порт.

VS Code: установите Go extension, создайте `.vscode/launch.json` с `program: "${workspaceFolder}/cmd/server"`, `mode: "debug"` и `envFile: "${workspaceFolder}/.env.crypto.local"`. Если использован другой local env path, задайте его явно. GoLand: Run → Edit Configurations → Go Build, Package path `metapus/cmd/server`; импортируйте то же окружение. Не добавляйте локальный файл с ключами в Git.

Список обязательных переменных и дополнительные dev defaults проверяйте в `scripts/dev/crypto-run-server.ps1` и runtime config. Для production-like tokenless Vault используйте отдельный public-test runbook, а не локальные dev-key настройки.

Первый breakpoint ставьте на создании `tenantdb.NewManager` в `cmd/server/main.go`; используйте имя функции, а не устаревающий номер строки. Затем проследите router и tenant middleware по [модулю 6](06-metapus-api-auth.md).
