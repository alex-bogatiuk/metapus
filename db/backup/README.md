# Локальные снимки тестовой БД

`snapshot-public-test.sh` сохраняет согласованные дампы meta и всех tenant БД
проекта Compose. На время выгрузки он останавливает API и worker и затем
возобновляет именно эти контейнеры с прежней конфигурацией. Новые снимки
создаются в отдельном каталоге с правами `0700`; файлы имеют права `0600`.

```bash
bash db/backup/snapshot-public-test.sh metapus-public-test
```

В снимке есть пользователи, сессии, MFA и финансовые данные. Содержимое
`db/backup` исключено из Git и Docker build context. Не добавляйте дампы в
исходники принудительно и не публикуйте их как артефакты CI.

Для проверки дампа:

```bash
cd db/backup/<имя-снимка>
shasum -a 256 -c SHA256SUMS
```

Восстанавливайте дампы только в пустые БД на изолированном стенде. Сначала
восстановите `tenants.dump`, затем все `mt_*.dump`; `globals.sql` нужен, если
целевой PostgreSQL ещё не содержит роль `metapus`. До запуска приложения
сверьте версию схемы с образом, `tenant_id` и имена БД.

Для PostgreSQL контейнера с ролью `metapus` и пустой БД `tenants` есть
проверяемая команда восстановления. Она откажется писать в исходный Compose
проект, в непустую meta БД или поверх существующей tenant БД:

```bash
bash db/backup/restore-postgres.sh \
  db/backup/<имя-снимка> <новый-postgres-контейнер>
```

Точный клон криптостенда требует также соответствующего Vault Raft snapshot,
unseal material, файлов состояния и сетевой конфигурации. БД сама по себе не
даёт работающие Vault-ключи и не должна запускаться с worker, подписывающим
операции другого стенда. Эти материалы хранятся вне репозитория. Для нового
независимого стенда используйте bootstrap с новыми ключами и wallets из
`docs/operations/public-nile-deployment.md`.
